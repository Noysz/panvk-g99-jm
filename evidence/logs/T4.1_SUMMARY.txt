The load-bearing case is 'voffset': indices {0,1,2} with vertexOffset=3
produced a byte-identical image to indices {3,4,5} with vertexOffset=0.
Two different API inputs, one image, so both the index fetch and the
vertexOffset addition are honoured.

'degen' {0,0,0} gave 0/4096, the negative control. 'zero' with
indexCount=0 emitted no vertex/tiler job at all and did not hang.

Zero GPU faults across 18 runs; every job exception_status = 0x01 (DONE).

SCOPE LIMIT: no vertex buffers are involved. The vertex shader indexes a
hardcoded position array with gl_VertexIndex, so this validates index
fetch and vertexOffset, NOT vertex attribute fetch. Also note v9 has no
index-buffer size field (see the upstream comment at
panvk_vX_cmd_draw.c:1044), so out-of-range index behaviour is undefined
by construction on this hardware and was deliberately not tested.
