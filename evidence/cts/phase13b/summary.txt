0072 command buffer re-submit
  Root cause: the MALLOC_VERTEX job writes the vertex packet pointer and
  strides into its own Draw.vertex_array; the reset before a re-submit did
  not put it back, so every later submit faulted (kbase 0x58). Found by
  diffing the descriptor pool before/after the first run (11 words changed:
  tiler heap, job status, Draw.vertex_array).
  resubmit_test/   tests/graphics/cube_test.c CUBE_RESUBMIT=1 (record once,
                   submit 30 times, pixel check every frame): 3x 30/30, 0
                   faults; PANVK_KBASE_SYNC_SUBMIT=1 and linear tiling PASS;
                   normal mode (record per frame) PASS. Control
                   PANVK_V9_NO_REISSUE_VA_RESET=1: 29/30 frames bad, 16
                   fault messages. CTS api.command_buffers (131): 55 P /
                   76 NS with and without the fix (no CTS case there
                   re-submits a draw).
  rR13/            CTS regression with 0071 + 0072: lost 0 vs rT13 and rA10b.
  drv23/aio_vk_cube/  AIO-Graphics-Test --cube vk (native Vulkan, prerecorded
                   command buffers) on the Android build: 0 faults; control
                   16 faults. 0.0.9 / 0.0.10 / 0070 had 16-1473 faults
                   (userlogs repro, same scene).
